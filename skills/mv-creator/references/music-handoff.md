# 交给 comfyui-minimax-music 之前：预填参数卡

comfyui-minimax-music 要求在成稿前逐项确定作品名称、用途、时长、听感、文件质量、采样率和 seed 策略。在 MV 流程里，这些大多已经能从创意简报和本流程推出。由你把它们整理成**一张预填好的参数卡**，用户一次确认即可，避免逐项来回问。

用户回复"确认"，等同于对卡中每一项做了选择（按该 skill 的规则记录为"用户已选"，推荐项记录为"用户确认推荐"）；用户只改某几项时，其余保持卡上的值。卡里写的是建议，没有经过用户确认前不要开始写 Caption 和 Lyrics。

## 这首歌是什么

MV 的歌曲是**从零创作、带人声演唱的完整原创歌曲**：新写歌词、新作旋律、由 AI 人声演唱，是整支 MV 的主体，画面围绕它展开。它不是给视频垫底的背景配乐，所以：

- 歌词要有完整的叙事和记得住的副歌 hook，与简报的故事起承转合呼应；
- 即使只有 30–60 秒，也要有完整的开头和收尾（结尾收束，不要像是从长歌里截下来的一段）；
- 人声是前景，编曲为演唱服务。

## 参数卡模板

| 项目 | 预填值 | 来源 |
| --- | --- | --- |
| 作品名称 | 推荐「……」；候选：「……」「……」 | 根据简报的副歌 hook 或核心画面拟定；也可沿用 MV 名称 |
| 作品类型与用途 | 原创人声演唱歌曲，作为 MV 主歌曲；导入剪映与画面合剪后发布到〈平台〉 | 简报 |
| 目标时长 | 约 N 秒，`max_duration` 设 N；结构：前奏 + 主歌 + 副歌 + 短尾声 | 简报 |
| 听感方向 | 主风格、速度感、情绪走向；简报没写清时给 2–3 个方向并标出推荐 | 简报 / 你的建议 |
| 人声 | 独唱/对唱、音色、演唱力度 | 简报 |
| 歌词 | 语言、叙事视角、副歌核心句（1–2 个候选） | 简报 |
| 文件格式与质量 | FLAC 无损留存（沿用工作流的保存节点）；剪映素材包会自动另转 48kHz WAV | MV 流程推荐 |
| 采样率 | 沿用源音频 | MV 流程推荐 |
| seed 策略 | 每版随机，mv-creator 记录每版 seed，可复现 | MV 流程推荐 |

卡后只问一句：「以上参数可以吗？回复"确认"，或告诉我要改哪几项。」

## 按时长安排歌词量

| 目标时长 | 建议结构 | 歌词量（参考） |
| --- | --- | --- |
| 30 秒 | 短前奏 2–4 秒 + 主歌 + 副歌 | 主歌 2–4 句，副歌 2–4 句 |
| 45 秒 | 前奏 + 主歌 + 副歌 + 尾声 | 主歌 4 句，副歌 4 句 |
| 60 秒 | 前奏 + 主歌 + 预副歌 + 副歌 + 尾声 | 主歌 4–6 句，副歌 4 句 |

模型可能比 `max_duration` 提前结束。成品时长以实际文件为准，`analyze` 和分镜会按实际时长切镜头，不需要为此重新生成。

## 成稿后的落地

- 文档按 comfyui-minimax-music 的模板保存到 `projects/<slug>/music/YYYY-MM-DD-安全化标题.md`（用户指定位置时优先）。
- Caption、Lyrics 原样另存为 `music/caption.txt`、`music/lyrics.txt`，供 `mv.py music` 注入工作流。
- 确定的歌名回填到 `brief.md` 的"歌名"一栏。
