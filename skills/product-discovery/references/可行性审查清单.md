# 可行性审查清单

> 用途：02 阶段五（Reality Check）的审查底稿。逐项过筛，命中的写入评估表并给降级方案。
> 原则：**只标风险不给出路 = 没做完**。每个 ⚠️ / ❌ 都必须配一个降级方案或一个验证动作。

---

## 一、技术可行性（只审 L 档与外部依赖项）

### 1.1 数据来源审查

| 来源类型 | 要问的问题 | 常见坑 |
|---------|----------|-------|
| 用户手动输入 | 用户凭什么愿意花时间录？第一次录入要多久？ | 录入门槛是 0-1 产品第一大流失点，超过 3 分钟基本没人录 |
| 第三方开放 API | 有官方 API 吗？免费额度多少？要企业资质吗？审核多久？ | 微信/抖音/小红书等平台的核心数据接口通常不对个人开放 |
| 网页抓取 | 目标站点是否禁止？抓的是不是个人信息？ | 反爬 + 合规双重风险，MVP 阶段不建议作为核心依赖 |
| 用户上传文件 | 格式有多少种？非标格式（扫描件/截图）占比多少？ | 解析非标文件的工作量常被低估 3-5 倍 |
| 系统间对接 | 对方系统愿意开接口吗？谁来推动？ | ToB 场景里，"客户 IT 部门配合"是不可控变量 |

### 1.2 技术依赖与成本

| 依赖类型 | 成本估算方式 | MVP 建议 |
|---------|------------|---------|
| 大模型 API | 按「单次请求 token 数 × 日活 × 使用频次 × 单价」估月成本 | 先估一遍，月成本超预算就降级（更小模型/缓存/限额） |
| 短信 / 验证码 | 条数 × 单价 | MVP 可先用邮箱或第三方登录替代 |
| 支付 | 需要企业资质 + 费率 + 结算周期 | 个人项目优先考虑第三方收款/买断码 |
| 地图 / OCR / 语音 | 免费额度 + 超额单价 | 关注免费额度是否够 MVP 验证期 |
| 服务器 / 存储 | 按量 or 包年，注意流量与存储增长 | 先用最小规格，别为想象中的规模买单 |

> **红线判断**：任何单项月成本超过用户预算的 30%，标 ⚠️ 并给降级方案。

### 1.3 高不确定性技术信号（出现即判 L 档）

- 实时协作 / 多端同步（涉及冲突合并、CRDT）
- 高并发或强一致性要求（抢购、库存扣减、金融记账）
- 自研算法（推荐、匹配、定价、风控）
- 音视频处理（转码、剪辑、实时通话）
- 跨平台深度集成（浏览器插件 + 桌面端 + 移动端同时要）
- 依赖尚未稳定的外部能力（未 GA 的 API、内测资格）
- 离线可用 + 同步（离线优先架构的复杂度常被低估）

### 1.4 规模预估

- 一期预期用户量级？（10 / 100 / 1000 / 10000）
- 单用户产生的数据量级？（条数、文件大小）
- 有没有明显的峰值时段？峰谷比多少？

> **提醒话术**：*"MVP 阶段按 100 用户设计就够了，为 10 万用户做架构是这个阶段最贵的浪费。"*

## 二、合规与风险红线

| 领域 | 红线行为 | 合规版降级方案 |
|------|---------|--------------|
| **医疗健康** | 给出诊断结论、推荐处方药、宣称疗效 | 只做信息整理、记录管理、科普内容聚合，明确"不构成医疗建议" |
| **金融投资** | 荐股、代客理财、承诺收益、无牌照放贷 | 只做数据可视化、记账、学习工具，不给买卖建议 |
| **法律** | 出具法律意见、代写具有法律效力的文书 | 做模板工具 + 明确免责声明，引导找执业律师 |
| **个人信息** | 未授权收集/存储身份证、人脸、通讯录、位置轨迹 | 最小必要原则，能不存就不存，需要则明示授权 |
| **爬取数据** | 抓取平台受保护数据、绕过登录、抓个人信息 | 改用官方 API、用户主动上传、或公开许可数据源 |
| **内容生成** | 生成内容无审核直接公开发布 | 加人工确认环节 + 敏感词过滤 |
| **未成年人** | 面向儿童收集信息、无家长同意机制 | MVP 阶段避开该人群，或加监护人验证 |
| **平台规则** | 违反微信/App Store/浏览器商店的分发与支付规则 | 上架前读一遍对应平台审核指南，规避已知禁区 |

> 命中红线时标 ❌，**不要说"这个做不了"**，说：*"这块直接做有合规风险，我们退一步：只做 A 不做 B，能保住 80% 的价值。"*

## 三、团队与资源

| 维度 | 审查问题 | 高风险信号 |
|------|---------|----------|
| 团队规模 | 有几个能写代码的人？投入是全职还是业余？ | 1 人业余 + MVP 超过 5 个功能 |
| 技术栈匹配 | MVP 需要的技术，团队做过吗？ | 核心功能用的是团队没碰过的技术栈 |
| 时间约束 | 期望上线时间 vs MVP 工作量 | 期望周期 < 工作量估算的 60% |
| 预算约束 | 每月能承担多少第三方服务成本？ | 依赖按量计费 API 且预算为 0 |
| 设计能力 | 有人做界面吗？还是用现成组件库？ | ToC 产品 + 无设计资源 + 强调"体验要好" |
| 运营投入 | 上线后谁来做内容/客服/拉新？ | 只有技术、无人负责运营的 ToC 产品 |

**时间约束判为高风险时，必须给具体砍量建议**，格式：
> *"按 2 人 3 周算，现在的 6 条 MVP 大概要 5 周。建议一期只留 1/2/4 这三条，3 和 5 放二期，6 直接砍——这样 3 周能交付并且核心流程完整。"*

## 四、冷启动与分发（0-1 产品最常见的死因）

### 4.1 首批用户获取路径审查

| 路径类型 | 可行性判断要点 | 典型触达量级 |
|---------|-------------|------------|
| 自己已有的社群/私域 | 群里有多少目标用户？关系强度？ | 10-100，最可靠 |
| 垂直社区发帖（论坛/小组/知乎/小红书） | 该社区允许自荐吗？历史同类帖反响？ | 50-500，看内容质量 |
| 一对一冷启（挨个找人聊） | 愿意花时间吗？一天能聊几个？ | 5-20，转化最高但不可规模化 |
| 内容运营（写文章/做视频） | 有持续产出能力吗？周期多长见效？ | 慢，3 个月起 |
| 朋友转介绍 | 产品是否有分享动机？ | 依赖产品本身 |
| 付费投放 | 预算多少？单个获客成本能承受吗？ | MVP 阶段通常不适用 |
| 寄生平台（插件/小程序/应用市场） | 平台有自然流量吗？审核门槛？ | 波动大，需评估平台依赖风险 |

> **判定标准**：说不出具体渠道，或只有"发到社交媒体上"，视为**未通过**，回到阶段一补齐。

### 4.2 说服门槛审查

用户从"看到"到"用起来"要跨过几道坎？每一道都会流失一半：

- [ ] 要不要注册？能不能先用后注册？
- [ ] 要不要迁移已有数据？迁移要多久？
- [ ] 要不要改变已有习惯？习惯的替代成本有多高？
- [ ] 要不要说服别人一起用？（多人协作类产品的最大门槛）
- [ ] 要不要付费才能体验核心价值？

### 4.3 平台依赖风险

- 产品是否寄生于某个平台（微信生态 / 某开放 API / 浏览器扩展 / 应用市场）？
- 该平台历史上有无政策收紧记录？
- 平台若关闭该能力，产品还剩什么？
- 有无退路（多平台并行 / 独立入口 / 数据可导出）？

---

## 五、审查输出格式

审查完成后，按 02 阶段五的三张表输出：

1. **技术可行性评估（聚焦项）** —— 含降级方案与象限修正
2. **团队与资源评估** —— 含具体砍量建议
3. **冷启动与分发** —— 含首批用户路径与关键分发假设

并检查阶段五的通过条件：

- [ ] 每个 ⚠️ / ❌ 项都有降级方案或验证动作
- [ ] 象限修正已回写阶段三并经用户确认
- [ ] 按量计费依赖已估出月成本量级
- [ ] 首批用户获取路径是具体渠道
