## 创作框架，不是爆款公式

本 Skill 的建议检查框架：**听觉辨识点 + 情绪代入 + 内容使用场景 + 全曲延展能力**。它是基于公开观察的工作假设，无概率系数或命中率。

| 检查 | 创作问题 | 可转成的决定 |
| --- | --- | --- |
| 听觉辨识点 | 记住一句词、旋律、节奏、音色还是停顿？ | 选一个主要 Hook，在后文保留和发展 |
| 情绪代入 | 替谁说什么，为什么与其当下处境有关？ | 具体口吻与情境，不把情绪词堆满描述 |
| 场景可用 | 毕业/旅行/运动/幽默等哪种画面会用？ | 人声密度、动作入口、转场意图或解说留白 |
| 参与入口 | 跟唱、舞蹈、问答、叙事还是安静陪伴？ | 设计可感的节奏或表达方式，不强求互动 |
| 全曲发展 | 片段之外为什么继续听？ | 主歌信息、段落反差、器乐发展和自然收尾 |

允许早展示辨识点，也允许叙事性铺垫。没有证据支持将“前三秒必须炸”“固定 BPM/和弦”“某种人声必爆”“统一副歌长度”设为规则。慢歌、器乐、方言、rap 都按实际目标判断；旋律上口、歌词短也不是唯一成功路径。

## 两种平台目标分别设计

抖音方向先确定歌曲是视频主体、舞蹈/转场配合，还是解说背景；按内容角色提出一个候选片段与用途。未取得音频只标段落/预期区间，不填实测切点，也不自动剪辑。

汽水或完整收听方向关注持续情绪、段落发展、重听理由与自然结尾；不能把短视频片段热度当完整歌曲留存。两种目标并存时确定主次，可设计同一作品的全曲与候选片段，不自动重写为两首歌。

治愈、搞怪、怀旧等只作方向候选：例如怀旧可以通过叙述视角、熟悉的音色或节奏语言体现，不必做老歌改编；国风通过具体音色/旋律语言选择，不自动加戏腔。场景与用户口味优先于流行分类。

## 用户要求当前榜单研究时

1. 确定目标平台、区域、时间窗口、榜单类型（热歌/飙升/原创等）及作品任务。只补缺口，不重问已知内容。
2. 优先可访问的官方榜单、平台公告与报告；没有能力取得时可用用户提供截图/表格/链接或可信报道，写清来源层级与读取限制。没有固定可用的官方数据接口时不编造接口，不索取账号。
3. 选择与目标相关且足以观察差异的样本，记录样本数与选择规则。可得时加入上升、稳定、未持续传播的对照，避免只看头部成功者；小样本不称统计规律。
4. 实际听取或分析后才记录音乐特征；仅拿到榜单/报道时只记录可确认事实，不能凭歌名猜 BPM、调性、音色、段落和 Hook 时间。
5. 提炼“可借鉴方法、适用场景、替代解释、验证办法”，再选少量与用户目标相关的策略。来源不足则降低结论强度，继续交付确定的创作文本，不阻塞私人创作。

单条样本至少记：作品/版本、来源 URL 与发布时间/访问日期、榜单及窗口、指标名称与单位、实际观察、证据类型/置信度、未确定项。速度/片段特征注明来自音频实测、人工试听还是报道；不同版本不能混在一起。

曝光、使用音乐的视频数、独立创作者数、播放、收藏、完播等不是同一指标，不跨平台相加或直接比较。区分累计值与窗口增量；算转化率需有同窗口同口径分母，没有就不算。单歌相关性不是结构带来成功的因果证据；推广、创作者覆盖、季节与事件可能共同影响。

## 回到提示词与验证

输出一张简表：“证据 → 本作品可用策略 → 具体段落/声部变化 → 适用限制 → 待验证结果”。研究数字和宣推内容留在文档研究章节，不粘贴 Caption/Style，更不混入 Lyrics。

试听前先检查是否表达目标、Hook 是否清楚、片段是否可用、全曲是否完整；之后才按用户提供的真实平台数据复盘。无发布数据时只说“候选传播设计”，不说“已验证爆款”。单次成功/失败都按 [feedback-learning.md](feedback-learning.md) 留在对应作品与上下文，不改写成通用规律。
