# Spoken Word、Rap Verse 与 Ad-lib

完整有人声歌曲在确定表演方案时读取；用户已指定其中元素时直接沿用。三者是可选的表演与编排设计，不是每首必加的结构，也不是模型的三个独立开关。纯器乐按 [instrumental-design.md](instrumental-design.md) 处理，跳过本页采访。

本页中文模块用于讨论创作意图；交付时按 [model-prompting.md](model-prompting.md) 转成目标模型默认的英文描述（用户指定语言优先），实际台词/唱词保留原语言，分别放正确字段，不把中文模块整段直接当默认模型输入。

## 先问一次，再设计选中的元素

在 D4 表演维度中处理。先给本曲推荐和一句理由，再问一个可多选的问题；不与用途、主题、曲风的未决问题一起发送：

> 这首歌要保持旋律演唱，还是加入 Spoken Word（旁白念白）、Rap Verse（说唱段）、Ad-lib（即兴衬词）？可多选，也可以都不要。

给用户的解释应具体：旁白像说一句心里话，说唱用节奏讲一段故事，衬词是在主唱空隙做短回应。不要只扔英文术语，也不要同时索要位置、字数、声线和每件乐器。

- 用户已有完整选择/拒绝：沿用，不重问；只有某项已明确或命中长期偏好时，只固定该项，其余仍未知的元素可合并问一次，不由“不要 rap”推断另外两项也不要，未提到不自动加入。
- 用户回答本问题“你定”：只委托该表演选择，记录 delegated；继续其他未完成维度。只有明确要求跳过咨询、直接出完整稿才走 Express。没有叙事需要可推荐旋律演唱，不能抵消原词保护、禁用人声或已选表演。
- 严格无人声：不问这三项；仅允许无词人声也不据此加入有词念白/说唱/衬词。只交歌词且不需要表演设计时可将本维度记不适用，但从零写词仍须了解用途、表达、内容权限等相关维度；局部润色或导出不重启整套咨询。
- 未回答且未委托：已问未答记 pending，尚未询问才记 not_asked，不把沉默记成同意或拒绝；可继续不依赖答案的设计，不交付擅加元素的定稿。

选择记录用 `not_applicable / not_asked / pending / selected / declined / delegated`，选中元素用 `spoken_word / rap_verse / ad_lib`，已拒绝元素可另列 `excluded`，来源另记。它是本作品选择，不是自动永久偏好。

## 先确定功能，再决定段落

Rap 是表演方式；Bridge 是段落功能。主歌可以说唱，桥段可以歌唱或器乐；不要将“中间一段 rap”当标准答案。

| 元素 | 服务的任务 | 设计重点 | 避免 |
| --- | --- | --- | --- |
| Spoken Word / 旁白念白 | 建场、内心话、故事转折或收束 | 相对位置、实际台词、说话感/语速/停顿、伴奏减法、接回歌唱 | 重述唱过的信息；默认耳语、舞台朗诵或拉长尾字 |
| Rap Verse / 说唱段 | 较密叙事、态度或节奏反差 | 清楚重音、气口、flow/切分、密度、是否旋律化、接唱方式 | 只写“全曲嘻哈”；为塞字破坏原词；突然改变已选风格 |
| Ad-lib / 即兴衬词 | 回应关键词、互动、点缀、推进气氛 | 哪些空隙、固定短词或自由范围、轻重与前后景、避开主词 | 逐句铺满；掩盖主唱；自动增加未经授权的短词 |

和声/合唱、哼唱、呼吸/叹息不等于上述三类，仍按本曲需要处理。自然换气无需往 Lyrics 填“吸气声”；“气口念白”影响方案时再区分气声说话、换气或叹息。

## 选中后补齐事件，不另发长问卷

已有信息沿用，其余给合理推荐；只有影响表达或权限的缺口每轮补 1–2 问。每个选中的事件明确：

**相对位置 → 谁表演 → 怎么说/唱 → 实际文本或即兴范围 → 伴奏变化 → 怎样衔接。**

1. 先说明它怎样服务核心命题，位置落实到相邻段落。秒点、拍数和长度只是 planned，不能承诺精准切入。
2. 确认同一叙述者还是另一角色、口吻、语速/重音/密度；未选性别或角色不随意指定，不保证固定真实声线。
3. 旁白必须有实际台词；固定衬词必须给出短词；自由 Ad-lib 可以只描述效果与允许范围，记录内容不可逐字保证，不伪造确定文本。
4. 选了元素不等于授权新增/改写受保护歌词。只准配曲时可将原句按节奏说或念；需要加词时先取得相应授权，未授权方案单列，不混入定稿。
5. 伴奏为文字让位，保留连续动机，说明如何回到主歌/副歌。多种元素可以分布不同位置，不默认同段叠加。

## 模型适配与标签的证据层级

| 层级 | 已知证据 | 使用方式 |
| --- | --- | --- |
| 输入字段 | 两模型各有描述和 Lyrics；没有独立三类人声开关 | MiniMax 表演放 Vocal Details，位置/减法/衔接放 Arrangement；YuE2 合并为自然 Style |
| 官方演示 | MiniMax 与 YuE2 的公开示例有念白、说唱及背景呼应；YuE2 有 `[Verse 1 – Rap]`、`[Vocal ad-libs]` 等写法 | 可以借鉴设计或做有来源的标签对照，不能再称完全没有官方用例 |
| 专用协议与实测 | 演示文本出现标签，不等于存在通用标签解析或已在本机稳定复现 | 不将 `[Rap]`、`[Spoken Word]`、`[Ad-lib]` 宣称为两模型可靠的专用 token；不保证逐句换唱法 |

默认优先由基础段落与相邻文本定位，描述承担表演控制；标签按各模型契约选择。YuE2 演示出现过 Intro/Bridge/Outro 等，但实验扩展写法与基础标签分开标明，不能照搬其他模型完整标签字典。

Lyrics 只放获授权的发声文本与所选段落标签。行号、角色标题、事件卡、“在此念白”、括号内制作指令可能被唱出，不当隐形控制。固定衬词可以单列，但单列或圆括号都不能保证背景轨归属；音量/声像/重叠是生成意图，不是已经分轨可精调的混音参数。

## 三类元素的模块示例

下面均为原创、未生成/试听的教学片段；不表示本首已选择，也不是用户真实经历。只有选中的元素才合入本曲。模块用于说明写法，实际交付仍返回受影响模型的完整新版描述与 Lyrics，不让用户自行拼碎片。

### Spoken Word：副歌后的说话式转折

- **实际台词示例**：`这次，我想听完自己的答案。`
- **MiniMax Vocal Details**：第一次副歌后的短段由同一主唱自然说出该句，语速稍缓，音高与停顿接近日常说话，不拖长句尾；其余段落保持原定旋律演唱。
- **MiniMax Arrangement**：这句念白时鼓与低频暂退，只保留原有和声动机的稀疏演奏；说完留短停顿，再由该动机接回最终副歌。
- **YuE2 Style**：在第一次副歌后加入一句同一主唱的自然口语念白，内容为“这次，我想听完自己的答案。”；稍慢、清楚、不拖长尾字，伴奏暂减到稀疏和声动机，短暂停顿后接回最终副歌的旋律歌唱。

实际句子同时放入 Lyrics 的对应段落，段落标签按模型选择。说话感不是耳语，也不是气声歌唱；若台词来自受保护原词，上例不得代换它。

### Rap Verse：主歌说唱，副歌接唱

- **授权代写时的短句示例**：`把回程的票收进口袋 / 沿着旧路数着站牌`。
- **MiniMax Vocal Details**：第一主歌用清楚的节奏说唱呈现现有短句，重音自然，轻微切分，句间留气口；是否带旋律按本曲选择，不把词尾强行拖长；副歌恢复舒展歌唱。
- **MiniMax Arrangement**：保留原定风格和核心律动，主歌减少抢字的填句；最后一行降低密度，让副歌旋律自然接入。
- **YuE2 Style**：仅第一主歌使用清楚、有自然重音和气口的中文节奏说唱，维持本曲原有风格与律动，伴奏为文字留白；末行稍放松密度，副歌回到舒展的旋律歌唱。

先检查文本是否适合按节奏说，不能用 flow 形容词修复过密长句。四行、某 BPM 或某种鼓型都不是统一要求。

### Ad-lib：主句之后的有限回应

- **指定短词示例**：最终副歌第一句后的空隙回应 `好啊`；第二句之后回应 `向前`。只有获授权才写入 Lyrics 对应位置。
- **MiniMax Vocal Details**：只在上述两处主唱停顿加入较轻的背景回应，避免重叠主词，其余段落不加衬词。
- **MiniMax Arrangement**：为两次回应留出短空隙，保持主唱在前景，随后继续原有乐句与收束。
- **YuE2 Style**：最终副歌仅在第一、第二句结束后的留白分别加入较轻的“好啊”和“向前”背景回应，声音处于主唱之后，不覆盖主歌词；其余段落保持简洁，收尾仍按原编排。

自由版本则删除指定短词，改为“仅在最终副歌句间做轻短无词回应，不增加新的叙事句”；须与用户允许的即兴范围相符。不能一边要求完全逐字、不得加词，一边允许任意即兴。严格无人声时以上固定和无词版本都排除。

## 事件卡与实际交付

```yaml
vocal_choice:
  status: selected
  elements: [spoken_word]
  source: user_explicit
vocal_events:
  - event_id: "VE-01"
    section_id: "B1"
    delivery: spoken_word
    purpose: "从犹豫转为自己作决定"
    content_source: "用户授权代写；教学示例"
    content_mode: fixed_text
    text: "这次，我想听完自己的答案。"
    position: "第一次副歌之后，最终副歌之前"
    length_plan: "一句"
    performer: "同一叙述者"
    performance: "自然说话，稍慢，不拖长尾字"
    accompaniment: "暂减鼓与低频，保留稀疏和声动机"
    transition: "短暂停顿后由原动机接回歌唱"
    rendering: "描述写表演与位置；获授权台词同时放 Lyrics"
    timestamp_status: planned
    start_sec: null
    end_sec: null
    verification: pending_listen
```

自由即兴用 `content_mode=free_within_scope`、`text=null`，另写允许范围；未选元素时 `vocal_events: []`。完整文档保持事件卡、段落、描述、Lyrics 四处一致，双模型实际交付分别给完整输入。

## 手动对照与验收

优先短结构单测一类事件；用户明确组合时保留选择，分项检查，不擅自删减。对照尽量保留已记录 seed 和其他已确认设置，不保证跨版本/硬件复现。

| 元素 | 真实音频需要核对 |
| --- | --- |
| 念白 | 是否真在说话，台词完整否，有无拖成旋律、吞词，前后衔接自然否 |
| 说唱 | 重音/节奏是否成立，有无挤字漏词，是否只在计划段落并接回歌唱 |
| 衬词 | 是否作为回应出现、固定词是否正确、有无盖主唱或扩散到其他段落 |

失败先查描述与 Lyrics 的位置、内容和全局要求是否冲突，再改一个主维度。没有音频时全部为 pending_listen，不记命中率、独立声轨或模型稳定性排名；不自动录制、分段生成、混音或运行服务。
