# 音频质量选择、参数映射与文件检查

引导用户选择音频质量、格式、码率、采样率或处理上传失败时读取。说明取舍并给可调整的建议，让用户选择；只有用户委托时才代为定参数，并注明理由。只要求创作文本时，不把文件检测设为前置条件，也不自动执行生成、转码、上传或联系平台。

## 先选择用途与质量取舍

“音质”至少有两层：制作听感，以及文件编码规格。让用户用熟悉的语言选择目标，再映射到真实控件；不能将某个格式、码率或采样率固化为所有作品的质量要求。

先问当前用途，如自己试听、分享、后期编辑或指定平台发布，再按用户关心的维度展开；每轮只补 1–2 个缺口。以下是可选方案，既不是统一质量等级，也不是每次必问的完整清单：

| 用户可选的方向 | 实际参数映射与取舍 |
| --- | --- |
| 偏小的 MP3 文件 | 已知官方保存选项有 `128k`；说明这是较低码率的有损编码，不承诺特定听感，也不把它当作快速生成模式 |
| 可变码率 MP3 | 官方界面的 `V0` 是可选质量档位；文件平均码率会变化，不适合承诺一个固定码率门槛 |
| 较高码率 MP3 | 已知官方选项有 `320k`；文件更大，编码档位并不证明生成内容质量或必然更好听 |
| 无损留存或后期处理 | 可选支持的 FLAC 等无损编码；只保留来源已有数据，不恢复有损文件丢失的细节。WAV 等格式能否直接保存需核对节点或后期工具 |
| 沿用源音频与现有设置 | 用户明确选择沿用时记录实际节点值；若未提供工作流，标为“沿用，具体值待核对”，不猜默认值 |
| 指定平台发布 | 读取本次平台要求，在允许范围内让用户选格式与相关参数；冲突时说明所选方案不能用于该目标，让用户决定调整导出方案或用途 |

制作听感可选自然亲密、清晰分层、饱满强烈或刻意 lo-fi 等方向，沿用用户艺术选择。文件质量偏好不能自动改写声线、风格或混音方向。

采样率单独处理：用户可以选择沿用来源，也可以因明确用途指定目标。来源已满足所选方案时保留；需要转换时先核对来源、目标和实际支持的处理环节。保存节点没有采样率控件时明确说明，不把目标值冒充模型输入。

记录“听感目标、格式、码率/模式、采样率、使用场景、参数来源”。尚未选择的项目保留待选；用户说“你来定”时按用途推荐，不自动套最高规格。时长按主流程同步记录，不从文件质量选项推导固定片长。

首次完整创作的未选项目不能只在成稿表中写“待选择”：当前轮应先给选项、等回答，再交付最终文本。质量选定后，继续主动给出采样率的“沿用/自定”和 seed 的“沿用/固定对照/新变体”选择；不要等用户自己想起这些参数。“帮我生成提示词”或只委托歌词并不授权代选它们。用户明确要求免提问时按授权范围推荐；格式、采样率实际值或节点映射未知可另标待核实。

## 听感写进 Caption

把具体听感自然写入 `Global Metadata` 或 `Vocal Details`，与编制和情绪一致。下面是可选择的自写片段，不是必须整段附加的咒语：

歌曲中强调主唱与伴奏的清晰关系：

```text
主唱清晰地处于前景，与伴奏保持明确的层次。低频均衡，高频平顺；副歌展开时保留自然的动态变化。
```

纯音乐中强调声部、瞬态与高潮余量：

```text
让主旋律乐器清晰地处于前景，支撑声部各有层次，低频受控。保留自然的起音，为最后一段的层次展开留出空间。
```

有意采用 lo-fi 或磁带质感时保留风格：

```text
保留刻意选择的磁带温暖感与轻微底噪，同时保持旋律清楚，避免低频遮住其他乐器。
```

只选符合当前作品的 1–2 句；人声、音色、空间和动态描述不应相互冲突。不要加入 `320 kbps`、`44.1 kHz`、`24-bit` 等文件指标来代替编码设置，不用“无损”“4K 音质”“保证过审”等无法由文本保证的承诺，也不一律增加立体声宽度、极高响度或强限制处理。

## 导出目标单独交付

生成参数与文件保存设置分开列出，所有目标来自本次已选方案或明确的对应平台规则。无目标、无文件或无检测证据时，不把推荐写成实测值：

| 项目 | 建议与条件 | 需要验证什么 |
| --- | --- | --- |
| 格式与留存 | 按用户选择列 MP3、支持的无损格式或沿用设置；无损副本可以推荐，不强制每次生成 | 实际格式、编码及所选用途的支持情况 |
| 码率与模式 | MP3 按已选 `128k`、`V0`、`320k` 或已核实的其他节点选项；只有本次选择或平台要求固定码率时才约束 CBR | 对照所选档位；用户选 VBR 时不能仅因平均值低于某个历史数字而判失败 |
| 采样率 | 列用户指定值、当前平台范围或明确选择沿用来源 | 检测实际音频流，再对照本次目标；没有门槛时不自行加最低值 |
| 时长 | 列用户目标、`max_duration` 上限及是否需要后期精确片长 | 检测实际时长；模型上限不等于准确片长保证 |
| 验证状态 | 分别列目标、来源、证据/实测值及状态；缺少目标或证据为 `PENDING`，违反本次明确要求为 `FAIL`，已核实满足该项为 `PASS` | 没有成品就写“文件待检查”；没有已选目标就写“待选择”，不能自动判失败 |

实际节点映射见 [workflow-contract.md](workflow-contract.md) 的“音频保存与导出字段”。未知节点时仅给目标值，标注“具体保存控件待映射”，不要凭空添加 `sample_rate`、`bit_depth` 等控件。模型原生输出采样率也不能根据保存节点的格式选项推定。

优先从生成时的原始音频数据或可用无损来源制作发布副本，避免多次有损编码。把低码率 MP3 转成 320 kbps 或 FLAC，不会恢复已经丢失的细节；升采样也不会恢复来源中不存在的高频信息。若仅存低质文件，说明来源限制与重新取得原始文件的选择，不把格式转换说成音质修复，也不自行生成新曲。

针对官方保存节点，先按所选格式操作：MP3 用 `SaveAudioAdvanced` 的 `format=mp3` 加用户所选 `quality`；旧 `SaveAudioMP3` 只设置所选 `quality`，它没有独立的格式控件。用户选 `V0` 时保留该选择，只有选固定码率时才改成对应值。两者都没有采样率控件。API/UI JSON 可能把 `quality` 放在动态 `format` 结构内，修改时依据真实 schema，不把界面标记直接编造成 JSON 输入。

## 上传失败时的最短检查路径

1. 先确认本次选择的发布目标，提取报错中的明确门槛，核对平台是否接受所选格式。若用途或目标未定，先引导选择，不把历史截图当成本次门槛。已有资料能回答时不重复采访作品方向。
2. 检查实际文件的音频编码、采样率和码率，再核对保存节点。沿实际音频连接定位保存节点，不依赖固定编号；确认检查的文件与本次保存输出一致。上传失败本身不能证明编曲或歌词有问题。
3. 对照本次目标判断；只有导出设置不符时才提出从原始来源重新导出。已选配置与文件不一致时，核对实际保存节点、路径、时间及是否拿到旧文件或二次压缩副本；不随意改歌词、seed 或声音风格。
4. 技术规格满足后，仍需试听主唱/主旋律清晰度、非预期失真、爆音、突兀截断与过长静音等问题。未拿到或未试听音频时明确该部分未验证；用户保留的艺术效果不按缺陷处理。

用户提供本地音频并需要检查时，可使用已安装的 `ffprobe` 只读查看；未安装时，可让用户查看播放器/编辑器中的编码属性，不为给提示词自动安装工具。PowerShell 示例：

```powershell
ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,sample_rate,channels,bit_rate:format=format_name,duration,bit_rate -of json 'D:\Music\song.mp3'
```

替换为实际路径，读取 JSON，不能仅看扩展名或文件体积。`sample_rate` 的单位是 Hz，`bit_rate` 的单位是 bit/s；例如 320,000 bit/s 对应 320 kbps。容器总码率与音频流码率可能不同，优先查看音频流；若字段缺失或为 `N/A`，标为无法据此判断，不能自动判失败或用容器总码率冒充音频码率。接近目标值的舍入差异结合编码设置核实，不仅凭一个显示数字作过严断言。

检查元数据只能确认文件技术信息，不能证明听感、原始来源质量或平台审核结果。只返回与任务有关的检测值，避免输出文件中无关的个人标签。

`ffprobe` 的流码率可以检查码率门槛，但单个平均值不能证明每帧均为 CBR；平台明确要求固定码率时，还需结合已知编码命令或可靠的码率模式检测。不要把缺失字段猜成某个默认值。

### 可复制的重导出方案

需要转换方案时提供；用户已要求处理音频时可在其授权范围内执行，只要求创作文本或修改 skill 时不自动转码。本机已安装 FFmpeg 时，优先从已有 FLAC/WAV 等无损来源编码，而不是再次编码现有 MP3。原始/无损来源需先检测采样率和声道。

下面仅演示用户**已选择固定码率 MP3**时的转换模板，码率由用户输入，不提供默认值；正式交付时可直接填入已选参数。用户选择 VBR、FLAC 或沿用时使用相应方案，不套用此命令。来源采样率与声道已符合所选方案时保留：

```powershell
$chosenBitrate = Read-Host '输入已选择且编码器支持的 MP3 固定码率（如 128k 或 320k）'
ffmpeg -n -i 'D:\Music\song.flac' -map 0:a:0 -c:a libmp3lame -b:a $chosenBitrate -abr 0 'D:\Music\song.selected.mp3'
```

只有来源与用户已选采样率要求不符、且本次需要转换时，才加入实际重采样；先核对目标受到编码器支持：

```powershell
$chosenBitrate = Read-Host '输入已选择且编码器支持的 MP3 固定码率'
$chosenSampleRate = Read-Host '输入已选择且编码器支持的采样率（Hz）'
ffmpeg -n -i 'D:\Music\song.flac' -map 0:a:0 -ar $chosenSampleRate -c:a libmp3lame -b:a $chosenBitrate -abr 0 'D:\Music\song.selected-resampled.mp3'
```

`-n` 保留同名既有文件；不要添加 `-c:a copy`，流复制不能改变码率或采样率。没有平台声道要求时不强制单声道转立体声；也不要自行改变响度、速度或剪辑。命令成功后用前面的 `ffprobe` 检查**新输出文件**，再报告实测值。重采样只改变技术规格，无法恢复原始来源缺失的细节，也不保证平台接受。
