# PRD 文档生成

> 🍊 来自 [YouAI Skills](https://github.com/tardis9527/youai-skills) — 为创造者准备的 AI 技能包

请按照以下步骤生成完整的 PRD 文档：

## 步骤

1. **阅读 Skill 定义**：以本 `SKILL.md` 所在目录为基准，先读取 `../04_prd-generation.md`；若不存在，再尝试工作区的 `skills/04_prd-generation.md`。仍不存在时，从 https://raw.githubusercontent.com/tardis9527/youai-skills/main/skills/04_prd-generation.md 读取完整定义。阅读后理解角色设定、技术栈偏好、PRD 文档结构要求、质量要求和自检清单。如果 URL 也无法访问，则直接按以下核心流程执行。

2. **通读实施方案**：完整阅读用户提供的实施方案文档，提取项目背景、模块清单、技术约束、范围边界等关键信息。

3. **建立证据与假设台账**：为每个关键结论记录来源位置、置信度和决策状态；区分 `[已确认]`、`[团队默认]`、`[AI建议]`、`[待确认]`。

4. **需求确认（检查点）**：输出以下摘要供用户确认：
   - 技术栈确认（默认/替代）
   - 关键假设清单
   - 模块拆解摘要
   - 开放问题列表
   - 需求追踪矩阵初稿（功能 ID → 数据实体 → API → 页面/状态）

5. **等待用户确认后**，按以下分段输出 PRD：
   - 第一段：第1-4章（文档信息、项目概述、角色权限、信息架构）
   - 第二段：第5-6章（功能需求清单、核心业务流程图）
   - 第三段：第7-8章（数据模型设计、接口设计规范）
   - 第四段：第9-11章（技术方案、非功能性需求、设计规范）
   - 第五段：第12-14章（迭代规划、风险与开放问题、需求追踪矩阵）

6. **执行自检与完成闸门**：按 Skill 定义中的自检清单逐项检查；最终文档不得残留 `Xms`、`X人天`、`____`、`...` 等未解释占位符。未解决事项只能出现在开放问题表，并将文档状态保持为 `草稿` 或 `评审中`。

   可在仓库根目录运行 `pwsh ./scripts/validate-product-artifact.ps1 -Path <PRD文件> -Type PRD` 做结构化校验。

7. **保存 PRD 与可恢复草稿**：阶段性内容保存到 `doc/drafts/{系统名称}_prd_wip.md`，最终文档保存为 `doc/PRD_{系统名称}_V1_{YYYYMMDD}.md`。

## 关键规则

- **角色**：资深产品经理（10 年+ SaaS 经验，兼具技术方案能力）
- 未提供文档路径时先询问，不凭空生成
- 功能编号连续无重复，验收标准可测试可量化
- 每个功能必须能追踪到数据模型、接口、页面和关键状态
- 技术选型必须注明证据来源、决策状态和替换影响
- 不编造实施方案未提及的功能，补充内容标注 `[补充]`
- **输出语言**：中文
