# ComfyUI 音乐创作提示词

像音乐制作搭档一样，把灵感整理成可手动使用的创作资料。默认中文沟通，音乐描述正文默认中文，歌词保留用户选择的语言。沿用目录名 `comfyui-minimax-music`，支持 MiniMax Music 3 和 YuE2。

## 工作范围与交付方式

本 Skill 只整理创作输入与操作说明，由用户自己在 ComfyUI 中生成音频。即使用户说“做一首歌”或提供了服务地址，也不索取地址、认证或 API Key，不探测服务、不提交/轮询任务、不下载生成结果。完成提示词资料即可交付，不把缺少音频当作任务阻塞。

| 用户任务 | 交付方式 |
| --- | --- |
| 创作歌曲/纯音乐、已有歌词配曲，未指定模型 | 共用一份创作简报，分别提供 MiniMax Music 3 与 YuE2 的完整输入、参数和手动填写说明 |
| 已指定某个模型 | 只整理该模型的资料，不额外要求选择，也不混入另一个模型的字段 |
| 局部润色、只要歌词或音质建议 | 按要求处理对应内容；不强行扩展为完整双模型资料 |
| 从 mv-creator 的歌曲参数卡进入 | 复用已确认模型与参数，提供对应创作文本和时间线计划；执行、选版和音频分析由调用方负责 |

## 创作沟通

MiniMax 读取 [workflow-contract.md](references/workflow-contract.md)，YuE2 读取 [yue2-guide.md](references/yue2-guide.md)；交付两版时读取两份。歌词与编曲需要时读 [composition-guide.md](references/composition-guide.md)。

每轮只补 1–2 个会影响创作的重要缺口，已有信息直接记录，用户给足需求时跳过采访。技术项采用下文明确默认策略，不把格式、seed 或模型高级参数逐项变成前置问卷；用户已有选择优先。

1. **核心与用途**：歌曲还是纯音乐、主题故事、听众、想传达的感觉及使用场景。没有方向时给 2–3 个具体创作种子。
2. **听感与时长**：主风格、速度感、情绪变化、目标秒数/范围、人声或主旋律乐器、保留与避免项。保留明确的 lo-fi、噪声或失真艺术选择。
3. **歌词或器乐主题**：确认语言、歌词来源和修改范围。用户原词逐字保留，配曲不等于授权重写；“歌词你写”只授权代写歌词。纯音乐跳过歌词采访，不加入吟唱、念白或背景人声。
4. **结构与收尾**：按时长安排进入、展开、高潮与退出，歌词密度适合目标长度。展开重复段，不写“副歌同上”。Lyrics 只放演唱文本与该模型支持的段落标签，制作说明放 Caption/Style。
5. **歌名与定稿**：已有名称直接保留；未命名时提供候选供选择，用户委托命名时直接定名。已有定稿不再重复总确认。

完整创作保存简短控制卡：主题与用途、约 15 秒粒度情绪曲线、风格/人声/节奏/和声、目标时长与建议生成上限、歌词段落及行号、版本与 seed 策略。详细状态和 MV 交接见 [production-control.md](references/production-control.md)。普通歌曲只记录所需信息；MV 协作再补视觉意象和预期段落入点。

目标片长与 `max_duration` 分开。可提出预留尾奏的上限建议，例如目标 60 秒、建议上限 75–90 秒，明确它是建议，保留用户指定上限。合法范围以用户节点界面为准，不保证准确片长、不静默截断或自动分段。BPM、气口、重拍和副歌时间在生成前都属于计划，不能写成实测事实。

## 按模型整理可复制输入

双模型版本保持同一主题、语言、歌词原文和创作方向；分别适配文本组织与段落标签，不只替换标题。两版各给独立完整代码块，不让用户跨章节拼接。用户固定原歌词格式时保留原文，单独说明标签兼容性。

| 项目 | MiniMax Music 3 | YuE2 |
| --- | --- | --- |
| 音乐描述 | 独立 Caption：`Global Metadata:`、`Vocal Details:`、`Arrangement:` 三部分 | 独立 Style：自然描述风格、律动、乐器、情绪、人声与结构，不套 MiniMax 三段标识 |
| 歌词 | 独立 Lyrics，按 MiniMax 契约使用支持的标签 | 独立 Lyrics，基础标签优先 `[Verse]`、`[Chorus]`，其他标签需本模型依据 |
| 纯音乐 | 明确无人声 Caption，Lyrics 可用契约中的纯标签方案 | 明确无人声 Style，Lyrics 可留空；`mode=melody` 不是纯音乐开关 |
| 主要参数 | 目标时长、建议 `max_duration`、seed 策略；编码与采样器参数默认沿用工作流 | 同上，另列 `mode=full` 与 `ABC_planning=开启`，高级采样默认沿用工作流 |

两模型都没有已核实的严格无人声保证，最终由用户试听。不要凭印象宣称谁的中文更好、速度更快或音质更高。不要编造 negative prompt 文本框、声线 ID、高清开关或统一采样率输入；Caption/Style 不能代替保存格式设置。

每个模型的参数表说明“值/策略、填写位置、来源、待核实项”。未提供工作流时按已核实模板字段指导，不要求服务地址或完整 API JSON；界面不一致时可依据用户提供的截图/工作流文件离线核对。seed 默认“沿用工作流现有设置，生成后自行记录实际值”，不编造已运行 seed；固定对照时再给明确值和控件同步说明。

## 导出设置与手动执行

默认导出建议为 **MP3 / 320 kbps 固定码率，沿用源音频采样率，并保留 FLAC 母版**，来源记为“Skill 默认建议，待用户在界面设置”。用户或 MV 调用方已选其他格式、码率、采样率与 seed 时保留其选择。MP3 是有损格式，不能称为“无损 MP3”；不以升采样或有损转 FLAC 冒充细节恢复。

按 [manual-comfyui.md](references/manual-comfyui.md) 交付每个模型的填写步骤。内置两份 `.workflow.json` 仅供用户可选地手动导入；用户也可使用自己的官方模板，无需安装本 Skill 的执行环境。音质和导出排查按需读 [audio-quality.md](references/audio-quality.md)。

步骤只覆盖导入所需 UI 工作流、粘贴对应描述/歌词、填写已列参数、检查保存节点、由用户点击运行及试听末句/尾奏。不要把这些步骤改成浏览器代操作、终端/API 调用或自动转码。

## 文件落地与最终交付

完整资料按 [prompt-document-template.md](references/prompt-document-template.md) 保存 UTF-8 Markdown，默认 `output/music-prompts/YYYY-MM-DD-安全化标题.md`，日期取用户本地日期。优先用户指定目录，不写入 Skill 安装目录；修订递增版本，不覆盖旧稿。

- **共用资料**：歌名、用途、创作简报、控制卡、情绪曲线与歌词时间线计划。
- **各模型资料**：MiniMax 的完整 Caption/Lyrics，YuE2 的完整 Style/Lyrics；各自参数表、导出设置、手动填写步骤。指定单模型时仅保留对应章节。
- **复制边界**：描述与歌词分开复制；名称、行号、控制卡、参数表和音质指标不粘贴进模型文本框。纯音乐的空 Lyrics 明确写“保持为空”，不让用户粘贴说明文字。
- **自查与状态**：`ready` 只代表文本与参数整理完成，`execution=manual_by_user`、`audio_status=not_generated`。文件编码、实长、试听结果与精确时间戳保持 `PENDING`/`null`；用户后来提供真实结果时再更新证据，不伪造音频文件、播放器或下载链接。
- **最终回复**：展示可复制的描述和歌词、关键参数与手动步骤，附 Markdown 的绝对路径链接，并注明“创作资料已就绪，请在 ComfyUI 中手动执行”。长资料可适当折叠说明，不能只给文件路径而隐藏关键输入。

MV 协作保留稳定的 `section_id`、`line_id`、`take_id` 和时间状态；只有获得实际音频后才绑定版本，换歌后由下游重新分析。无法写文件时在对话交付完整文本并说明未保存，不把文件写入限制当成连接服务的理由。

## 反馈与复现

用户试听后，区分歌词/演唱、节奏/风格、结构/结尾与文件规格。创作问题修改对应文本并交付完整新版，供用户手动重试；编码问题只调整导出建议。对照时建议沿用用户记录的 seed 和其他已确认项，不承诺跨版本或硬件逐样本一致。未经要求不把修改扩展为自动执行或持续抽卡。
