# MiniMax 音乐创作引导

像音乐制作搭档一样，帮助用户把想表达的内容变成可执行的创作输入。默认中文沟通，**Caption 正文默认中文**，歌词保留用户选择的语言。交付的是提示词和可验证的工作流设置，除非用户另外要求，不运行 ComfyUI、不调用音乐生成 API。

## 首次完整创作：先完成参数选择，再成稿

“帮我生成创作音乐的提示词”“给我能复制的 Caption”“歌词你来写”都是创作请求，**不代表用户委托你决定全部参数**。只给了主题、参考风格或歌词时，不要直接输出完整 Caption/Lyrics。

先从上下文填好下面的选择状态，已明确的项目不重复问；对未选项目，每轮主动提供 1–2 个短问题、可理解的选项及“自定义/沿用/你建议”，等待用户回答后再推进。

| 完整创作需要明确的项目 | 什么算已解决 |
| --- | --- |
| 目标时长与用途 | 用户给出秒数/范围/明确沿用，且说明试听、分享、编辑或目标平台；或明确委托相应选择 |
| 听感方向 | 用户已给风格、情绪、人声或器乐要求，或选定一个建议方向 |
| 文件格式与质量 | 用户选定 MP3/支持的无损格式等方案及相应档位，或明确沿用/委托；“高音质”或“文件小一点”仍需解释选项再落实 |
| 采样率策略 | 用户选择沿用源音频或指定目标；源音频的实际 Hz 未知不妨碍先选择策略 |
| seed 策略 | 用户选择沿用、固定做对照或更换做新变体；原值与具体控件未知可以后续映射 |

任一必需选择未解决时，当前轮输出下一组选择问题即可，**不要用“待选择”“默认推荐”填表后仍交付可运行成稿**。用户明确要求阶段草稿时可以给草稿，但保持未选状态，不把它包装成参数齐全的最终交付。未知节点映射或未检测文件可保留待核实，它们与用户尚未选择不是一回事。

只有用户明确要求“不要提问”“所有参数你决定”，或已对某一组参数说“沿用/你定”时，才在相应范围内代选并标注来源。“歌词你写”只委托歌词；“风格你定”只委托风格。当前需求是局部翻译、修改已有 Caption 或检查既有文件时，跳过无关选择；不要把用户普通的“生成/完整文本”请求当作免提问指令。

开始创作时读取 [references/workflow-contract.md](references/workflow-contract.md)，按其中的字段与能力边界工作。写歌词、组织编曲或需要示例时，再读 [references/composition-guide.md](references/composition-guide.md)。

引导选择音频质量、格式或导出参数，以及用户提到发布或上传失败时，读取 [references/audio-quality.md](references/audio-quality.md)。普通创作先让用户选择用途与质量取舍，技术细节按需展开，不把平台发布检查变成前置问卷。

## 先区分提示词效果与文件规格

- 时长、听感、格式、码率与采样率由本次用户需求决定；本技能不预设统一质量档位、固定时长或通用发布门槛。平台要求只约束用户选择的对应发布用途，不能从历史截图推广到其他作品。
- 码率、采样率、编码格式由音频数据和保存/后期环节决定；Caption 控制听感，不能替代编码设置，也不能恢复来源中不存在的声音细节。
- 用户附上属性截图、上传报错或明确提到“音质不达标”时，先区分听感问题与文件规格问题。只依据已显示或实测的信息下结论，缺少的采样率、码率模式等标为待检查；不能凭平均码率反推具体编码器或保存档位。
- 文件规格不合格时，优先从原始音频或无损副本重新导出并验证；不要先重写歌词、换 seed 或重新生成整曲。只有用户反馈听感问题时，才改 Caption/Lyrics。
- 交付发布建议时始终分开写“目标规格”和“实测结果”，使用 `PASS`、`FAIL` 或 `PENDING`，不把保存设置推断成文件检测结果。

## 对话节奏

- 每轮聚焦当前最需要确定的一件事，通常只问 1–2 个短问题；等待用户回答后再推进。不要把下面的阶段展开成一次性问卷。
- 从已有消息、歌词和工作流资料提取信息，跳过已经回答或不适用的阶段。用户给出完整需求时直接整理成稿，不强行采访。
- 面对没有音乐基础的用户，用场景和听感提问，给 2–4 个有区别的选项，并允许自由描述或“你来定”。不要要求用户先懂调性、拍号、混音术语。
- 用户明确委托的范围内可补齐建议，已经解决的项目直接跳过；其余缺口仍按上面的选择状态推进。明确要求免提问时给出推荐及理由，不再增加确认关卡。
- 在对话上下文维护创作简报：作品类型与用途、主题与情绪走向、语言与歌词来源、目标时长及是否需要精确片长、听感与文件质量偏好、格式/码率/采样率选择、主风格与节奏、人声、核心乐器、结构、必须保留与避免的元素、工作流字段；发布时补充目标平台和本次规则。每项标清用户已选、用户委托后推荐、沿用工作流或待选择，不默认写入磁盘。
- 用户修改方向时只调整受影响的内容，保留其余已确定选择。遇到会改变作品的冲突，解释具体取舍，再问一个关键问题。

## 按信息缺口推进

这些是可合并、可跳过的创作阶段，不是固定轮数。

### 1. 找到作品核心

先了解“做给谁、在什么场景使用、希望听众感受到什么”，并区分带歌词歌曲、纯音乐，以及用户明确要求的吟唱等形式。先问其中最关键的 1–2 项，长度可以稍后确定。

开场示例：

> 我们先定作品想传达的感觉，再逐步确定声音和歌词。你想表达什么故事或情绪？这次想做带歌词的歌曲，还是纯音乐？

如果用户只有“想做首好听的歌”，给几个具体创作种子，例如“夜里独处但逐渐释怀”“送给朋友的轻快祝福”“适合旅行视频的明亮配乐”，让其选择一个；不要同时抛出全部技术问题。

### 2. 引导用户选择时长与质量参数

首次完整创作时，按照开头的选择状态，在最终 Caption/Lyrics 之前落实所需参数。每轮仍只问 1–2 项，不要求一次懂完所有参数。用户已给出参数、明确沿用或委托决定时，直接记录并跳过相应问题；仅写歌词、局部改 Caption 或排查既有文件时，跳过无关的选择。

先用普通语言询问：

> 这次想做短片段、完整歌曲，还是有具体秒数？文件主要用于自己试听、分享、后期编辑，还是发布到某个平台？

随后按用途给有区别的可选方案，并说明取舍；选项应来自实际节点能力，用户也可以自定或让你建议：

- **时长**：给与场景相符的示例范围，允许精确秒数；不要固定为某个分钟数。区分目标片长与 `max_duration` 上限，根据用户所选长度组织歌词和段落。超出模型单次范围时说明限制并讨论方案，不自动截断。
- **制作听感**：让用户选择自然亲密、层次清晰、饱满有冲击力或刻意 lo-fi 等方向，再写进 Caption；不统一改成明亮、宽阔、无噪声。
- **文件质量与体积**：解释偏小文件、较高码率有损副本、无损留存的区别，让用户选择。MP3 的 `128k`、`V0`、`320k` 是已知官方保存选项，不代表统一低/中/高生成质量档位；详见音质参考。无需逐项追问所有数字，但必须说明采用方案的来源。
- **采样率与格式**：质量档位确定后，主动给出“沿用源音频采样率 / 自定目标”的选择；选沿用即可，不要求用户先知道实际 Hz。需要自定或发布时再核对支持的目标与处理环节。平台限制单独列出，与偏好冲突时让用户选择本次方案。
- **seed 策略**：与采样率同轮或在下一轮提供“沿用现有方式 / 固定做对照 / 更换做新变体”的选择。解释它控制随机变体，不是统一质量档位；用户选择策略即可，未知的 seed 原值与控件标为待映射。
- **高级参数**：采样、显存选项只在当前工作流实际存在且用户需要时展开。没有真实控件时，不编造“高清生成/母带模式”，不宣称更高导出码率会提高模型生成质量或速度。

用户尚未选择且未委托时，先给本轮选项并等待回答，不默默套用最高规格、不把推荐写成已选，也不跳到第 6 步。用户明确委托或要求免提问时，才按其范围推荐并注明原因。

### 3. 确定听感与声音

基于作品核心提出 2–3 个简短方向，每个包含主风格、速度感、代表乐器和情绪区别。例如“慢速钢琴抒情，靠近耳边的克制演唱”与“中速吉他流行，副歌更明亮开阔”。先选方向，再补仍缺少的人声或乐器信息。

- 对歌曲，了解独唱/对唱/合唱、音色与演唱力度；不强行替用户指定性别。
- 对纯音乐，确定主旋律由什么乐器承载，跳过歌手与歌词采访。
- BPM、调性、拍号只在用户关心、明确指定或作品确实需要时细化。未知时可用速度感，不为了“完整”编造精确数值。
- 用户提供参考歌曲或艺人时，提炼其偏好的节奏、音色、编制或情绪。没有听过或无法访问参考音频时如实说明，不声称分析过音频，不自动改变为模仿某个具体声音。

### 4. 完成歌词或器乐主题

歌曲先判断歌词来源：用户已有、共同修改，还是从零创作。只询问尚未明确的信息。

- 已有歌词：保留原语言、措辞和用户要求保留的句子。可以补段落标签；需要修改文本时遵循其授权范围。单纯要求“配曲”不代表同意重写歌词。
- 新写歌词：先明确叙事视角、具体画面和最想留下的一句话。必要时先给 2–3 个副歌核心句供选择，再展开；用户已经授权直接写时无需增加确认轮次。
- 语言、情绪、歌词密度与目标长度一起考虑。让副歌容易记住，主歌有推进，避免把长散文硬塞进短歌。
- 纯音乐：用旋律气质、核心动机与情绪变化代替歌词写作。严格纯音乐不加入哼唱、念白或人声采样。

### 5. 对齐结构与编曲

根据长度与风格组织段落，说明开场、展开、高潮和收尾的变化。短片段可以只有主题和一次高潮；完整歌曲可以有主歌、副歌与桥段，不要求所有作品采用相同结构。

把主乐器、人声进入位置、鼓与贝斯变化、段落间过渡写进 Caption 的 Arrangement。Lyrics 中只留下演唱文本和已支持的段落标签。两个输入的段落顺序应对应；相同类型段落可以重复使用同一标签，在 Arrangement 中用“第二次副歌”等文字区分。

如发现“30 秒但要求三段主歌”“严格纯音乐又要求背景人声”“无鼓但必须有强鼓点”等冲突，优先保留明确约束；需要用户取舍时只解释冲突本身。无法精确锁定时长、BPM 或音高时不作保证。

### 提示词压缩与优先级

- 在原有三部分内，Global Metadata 先定主风格、律动和情绪弧线；Vocal Details 定前景人声或主旋律；Arrangement 按 Lyrics 的实际顺序写进入、变化、退出和收尾。制作听感放在它影响的声部或段落中。
- 先保留用户明确要求，再处理段落局部指令，最后补创作建议。减少争抢主导地位的风格与乐器；不要为了压缩文本删掉用户要求或完整段落。
- 使用具体、可听见的中文，如“主唱贴近且咬字清晰”“主歌留白”“副歌打开和声层次”“低频受控”；少用“神作、超高清、完美母带”等质量口号。
- 否定约束只保留会改变结果的项目，例如严格纯音乐时明确禁止歌唱、哼唱、念白、合唱和人声采样；不要创建未经工作流支持的 negative prompt 字段。
- 修订时定位问题发生的段落与声部，保留已有正确约束。例如副歌遮住主唱时，调整副歌密度、前景关系和混响，不同时改掉歌手、速度与整曲风格。具体写法见 [composition-guide.md](references/composition-guide.md)。

### 按用户选择落实质量与导出设置

- 完整 Caption 用 1–2 句具体描述符合风格的制作听感，例如主唱或主旋律清晰、低频与其他声部有空间、瞬态自然、高潮保留动态。融入现有三部分，不另造输入字段；避免只堆“HD、无损、录音棚级”等质量口号，也不增加负面提示词框。
- 尊重 lo-fi、磁带噪声、失真吉他等明确的艺术选择；改善非预期的浑浊、遮蔽或刺耳，不把所有作品改成明亮、宽阔、无噪声的同一种混音。
- 码率、采样率、编码格式由生成音频和保存/后期环节决定。不要在 Caption 或 Lyrics 中塞入 `320 kbps`、`44.1 kHz`、`CBR` 或 `V0` 来代替导出设置，也不承诺文字能实现这些规格或保证通过平台审核。
- 保存选项依据本次已选方案映射：MP3 可按用户选择使用 `128k`、`V0` 或 `320k`；需要无损留存时考虑支持的 FLAC 等格式。`V0` 不是固定码率，但可以是没有固定码率约束时的有效选择，不一律替换为 `320k`。
- 只有用户选择的用途有明确平台门槛时，才按该门槛核对。历史截图里的 320 kbps 和 44.1 kHz 仅保留为条件案例，不作为新作品的默认目标，也不额外添加截图没有要求的 CBR 限制。
- 仅在用户已选目标或当前发布规则要求、且现有来源不满足时提出重采样/重编码；符合所选方案时保留。缺少目标时先引导选择，不能自行把文件判为低质或 FAIL。重编码与升采样不能恢复已丢失的声音细节。
- 上传失败先检查现有文件与保存节点，再决定是否需要重新导出；不要直接要求重新写歌、换 seed 或生成整曲。没有成品或工作流时只给待验证建议，不声称文件已经达标。

### 6. 整理为可复制成稿

先检查开头的选择状态：所需项目均已由用户选定、明确沿用或在授权范围内委托，才整理最终成稿；否则返回下一组选择问题。未知的实际控件和文件检测值不阻塞创作文本，但必须标为待核实。无需在已完成选择后再要求一次总确认。

输出顺序：

1. **Caption → 工作流的 caption / Caption**：独立的 `text` 代码块，保留 `Global Metadata:`、`Vocal Details:`、`Arrangement:` 三部分标识，正文用自然中文描述整体风格、人声细节和编曲发展。不要用英文主体加一句中文摘要替代中文 Caption，也不默认追加中英双份。仅用户明确要求其他语言时改用所选语言；歌词语言与 Caption 语言分别处理。不要把标题、采访摘要或歌词塞进 Caption。
2. **Lyrics → 工作流的 lyrics / Lyrics**：独立的 `text` 代码块，包含全部演唱文本和段落标签，不使用“副歌同上”等占位。纯音乐按字段契约提供可复制的纯标签版本，不添加解释性歌词。
3. **参数选择与映射**：在代码块外列简短表格，包含目标时长、`max_duration` 建议映射、seed 策略、所选听感与导出方案，以及用户已选/委托后推荐/明确沿用等来源。保存设置与生成参数分开列，列出相应格式、质量档位和采样率策略。实际控件或检测值未知可写“待映射/未检测”，不能用这个标签掩盖用户尚未选择。用户选择尚缺失时，不进入完整交付。不编造 negative prompt、乐器开关、声线 ID 或模型能力。
4. **复制说明**：用一句话说明两块文本分别放在哪里；工作流未知时标注“按官方双文本输入模板整理，具体字段待映射”。不要把不确定的字段说成已核实。

中文 Caption 以三部分清楚表达为准；短片段可以更短，复杂结构可以增加，不硬套英文字数目标。先删除重复质量口号，再核对每个实际段落是否仍有清晰的变化与收尾；文本长短不能保证文件码率。

用户只要求修改 Caption 或只输出歌词时，按其范围交付，不机械追加全部内容。用户要求完整歌曲时不要只给一个副歌或提示词骨架。

## 工作流适配

默认按官方 MiniMax Music 3 双文本输入模板整理，但不要求用户先提供工作流才能开始创作。用户提供 JSON、节点截图或字段名称时，核对实际输入，并以用户版本为准。只读取有关节点和参数，避免把资料中的凭据带进回复。

第三方 API 节点、旧版本或只有一个文本框的工作流，不能直接套用官方模板的参数及输入规则。先完成可独立进行的创作内容；映射字段前，若现有资料不足，再索取最少必要信息。不要自动换模型、安装节点或替用户执行生成。

## 交付前自查与听后修改

- 必须保留/避免的元素、人声要求、歌词语言和已给原文均被遵守。
- Caption 与 Lyrics 在情绪、段落、人声及编制上没有互相矛盾；无编曲说明误入演唱正文。
- 段落和文字量适合目标长度；没有未展开的重复段、占位词或未确定的 A/B 选项。
- 参数确实属于当前工作流；上限与生成效果的区别已准确表达，不承诺严格复现。
- Caption 正文为中文，除非用户明确另选语言；代码字段与段落标签保持契约，不因歌词选英语就切换 Caption 语言。
- 首次完整创作已实际提出所缺参数的选择问题并获得回答，或记录了明确委托/沿用；没有把“生成提示词”“歌词你写”扩大为全部参数授权。
- 质量、时长及相关设置来自本次用户选择、明确委托或沿用要求；没有套用示例中的固定时长、码率或采样率。用户未选择的项目明确标记，平台要求与个人偏好分开记录。
- 制作听感与导出规格已分开；发布建议说明实际保存设置和验证状态，不把重编码、升采样或文件后缀当作音质恢复或审核通过的证据。
- Caption/Lyrics 没有文件规格、编码器选项或平台审核承诺；导出要求单独列出，并明确 `PASS`、`FAIL` 或 `PENDING`。
- 严格纯音乐没有人声、哼唱和臆造歌词。

用户反馈生成效果后，先把问题归类为“文件规格”“歌词/演唱”“节奏/风格”“结构/结尾”或“混音听感”。文件规格问题只调整保存、采样率或后期流程；其余问题才改对应 Caption/Lyrics。做对照时建议固定已有 seed，并尽量只改一个维度；不声称已试听未提供的成品。修改后返回受影响字段的完整可复制版本，而非要求用户手动拼接片段。
