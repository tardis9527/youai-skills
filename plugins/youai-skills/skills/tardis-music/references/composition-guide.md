# 词曲蓝图与编曲设计

完整创作时读取；这是创作方法，不新增模型能力。按当前缺口选择维度，不把清单变成用户必须逐项回答的问卷。先理解 [creative-intent.md](creative-intent.md)，特殊表演按需读 [vocal-performance.md](vocal-performance.md)。

## 从命题到词曲蓝图

先用一句话说清“谁对谁、借什么事件、表达什么”，再写本作品成功标准。每个主要选择附一句作用即可，避免堆音乐术语或冗长过程。没有用户故事时可以创作虚构情境，但应标“创作设定”，不冒充用户真实经历。

| 维度 | 需要作出的决定 | 自查 |
| --- | --- | --- |
| 歌词主题 | 叙述视角、具体细节、核心句、情绪转折 | 人称/时间线一致，核心句不是泛化口号 |
| 旋律身份 | 短动机、节奏轮廓、级进/跳进倾向、音区与句尾走向 | 主副歌有关系，Hook 可辨认而不过度重复 |
| 节奏与律动 | 稳定/切分/摇摆、疏密、重拍作用与段落变化 | 服务场景；不将“燃”固定等同高速 |
| 和声意图 | 安定/悬念/释放、循环感、必要的转折 | 和声与情绪关系明确，不强塞升调或通用和弦套路 |
| 人声表演 | 叙述、倾诉、宣告、对话；音色/咬字/力度/和声 | 人声在段落中的作用明确，纯音乐改为主旋律乐器 |
| 编曲与结构 | 声部职责、密度与音区变化、过渡、完整收尾 | 谁在前景、什么进入/退出、为什么变化 |

只是文字设计时写 `planned`，不能声称已经作出并听过旋律、得到 MIDI/乐谱或准确音高。用户明确要求精确乐谱属于额外交付，需按可用能力处理，不能以 Caption 冒充。调号、BPM、拍号、和弦不是普通创作必须填满的字段；有用户指定时保留，未指定可描述音乐意图。

## 歌词写作与可唱性

- 主歌提供具体人物、动作和处境；副歌凝练核心态度；预副歌负责起势时才添加；桥段提供新角度或转折，不默认每首都需要。
- 从可见/可听的细节取材，如收拾房间、车站、旧照片中的动作。不要以“梦想、远方、星辰”替代所有故事，也不把同一个场景套给所有用户。
- 用角色会说的话。叙述视角、人称、时态与称呼保持一致；未经授权不增加现实人物信息。
- 自然朗读，检查语义重音、词组断句、连续辅音/难咬字处、长句密度和预期换气。中文多音字、同音歧义、方言按实际需要指出；未生成时只能是文本可唱性检查，不等于已验证唱法。
- 相邻乐句可有相近密度但不机械等字数；押韵服务意思，不能为押韵牺牲语义。rap 可以更密，但要留重音和呼吸，不等于不断塞字。
- 适合延长的核心词可用于句尾，是否真有长音待试听；不把标点、破折号、括号或重复字母当作可靠的演唱指令。
- 核心句可重复形成识别，后次通过视角、和声或配器发展。所有实际演唱重复段写全，不用“同上”；用户指定逐字重复照做。
- 用户原词逐字保留，删行、改词、改语言、加台词需在授权范围内。原词过密时先说明与长度的冲突，建议延长/分配器乐或请求允许删改，不静默截断。

## 旋律与 Hook

Hook 可以来自一句歌词、一个旋律动机、节奏、音色或一次留白，不必同时具备。先选主要辨识点，再让其他元素支持它。

设计旋律时考虑：主歌与副歌的相似动机如何建立统一；音域或句长如何形成反差；哪个词承载情绪峰值；结尾是落定还是悬置。高音和更大音量并非唯一高潮，可以用更稀疏的伴奏、更近的人声或节奏停顿形成重点。氛围曲、民谣、舞曲各有发展方式，不套统一“主歌低—副歌高—末段升调”。

例：主歌用窄音区与短句讲述；副歌保留节奏动机但让旋律更舒展，核心句落在可记忆的重复轮廓；第二次副歌不改用户原词，通过呼应声部推进。这是生成意图，不保证音符或时点。

## 从感受转成具体选择

| 用户语言 | 可以推荐的音乐方向 | 需要保留的区别 |
| --- | --- | --- |
| 治愈温暖 | 柔和触键、木质音色、稀疏节奏、自然空间 | 可以平静，也可以逐步明亮；不自动加雨声 |
| 孤独但不绝望 | 主歌留白，后段扩展音区或和声 | 不把全曲写成持续悲伤 |
| 燃、有力量 | 明确重拍、推动低音、高潮打开声部 | 摇滚、电子、管弦的能量来源不同 |
| 轻松搞怪 | 节奏停顿、问答、反差音色、易参与动作 | 不默认童声、变声或低俗口号 |
| 国风 | 选择具体民族音色或旋律语言，再定现代底色 | 不堆古筝/二胡/戏腔；不把“古典”当单件乐器 |
| 适合讲解 | 稳定律动、克制旋律、较低密度 | 先确认有无解说，避免抢中频和注意力 |

一个主方向与少量有作用的融合元素通常更清晰；用户明确融合时保留其选择，不强行简化为单风格。

## 声部职责与段落事件

| 职责 | 可用材料 | 主要决定 |
| --- | --- | --- |
| 节奏 | 鼓、打击乐、节奏吉他 | 律动、推进、停顿、疏密 |
| 低频 | 贝斯、合成低音、钢琴低音 | 支撑还是参与旋律；如何与底鼓合作 |
| 和声 | 钢琴、吉他、弦乐、Pad | 轮廓、留白、包围感 |
| 主旋律与回应 | 主唱或主奏乐器、短填句 | 前景与呼应关系，避免抢主词 |
| 场景质感 | 雨、海浪、街道、磁带噪声 | 叙事理由、出现范围、是否遮挡歌词 |

不逐个问“要不要鼓、贝斯、钢琴”；先根据目标推荐最小编制，再询问确有差异的选择。明确无鼓时不能用“为了高潮”加打击乐；保留用户有意选择的 lo-fi、噪声与失真。

每段写清功能、前景、表演、进入/退出、能量变化、衔接与结尾。间奏可以发展动机、给叙事呼吸，不只是填满时长。歌词短、目标长时合理留器乐空间；段落数量、行数不能推算成可靠秒数。模型描述与 Lyrics 段落一致，不能凭空加桥段。

## 提示词装配与自查

先整理完整蓝图，再提炼为模型文本：整体方向 → 表演身份 → 按顺序的段落事件 → 核心约束与收尾。每个限制注明全曲还是局部，避免“主唱极度气声”与“全曲每字强烈有力”等矛盾。确需反差时分配到不同段落。

MiniMax 渲染为三部分 Caption，YuE2 渲染为自然 Style。描述要具体到行为，如“副歌通过展开吉他和弦增加层次，缩短主唱混响尾音，减少抢主词的填句”，不自动追加 `best quality, lossless, 320 kbps, perfect mastering`。文件指标放导出表。

交付前检查：意图与歌词是否一致；描述与实际段落是否对应；主词与特殊人声是否获授权；纯音乐/禁鼓等硬约束是否贯穿；两模型是否保持同一原词与方向；是否混入未核实标签或虚构实测。

## 不同输入的工作示例

### 模糊纪念需求

“想做首送给毕业朋友的歌，但不懂音乐。”

先问希望留下不舍、感谢还是期待，以及一个共同细节；歌词语言已有则不重问。不要第一轮问 BPM、seed、全部乐器和完整故事。得到足够信息后推荐听感，不虚构寝室或校园经历为用户事实。

### 方向完整，直接整理

“约 60 秒的中文暖心歌，轻柔女声、木吉他、不要鼓，下班回家，歌词和歌名你写，剩下你定，直接给 MiniMax 完整文本。”

无需再选模型、命名或技术参数。可委托定名《一盏灯等我回来》，设计“疲惫 → 放松 → 安定”的短结构，推荐适量尾奏上限并标来源；用户明确 `max_duration=60` 则保留 60。MP3 320k、源采样率、FLAC 母版、seed 沿用作为默认建议。给完整 Caption/Lyrics 和手动步骤，实长/试听 PENDING。

### 严格纯音乐

“40 秒科普视频配乐，轻快钢琴、拨弦，不能有人声，也不能抢解说，直接出稿。”

场景和限制已足够，跳过歌词/歌手/rap 采访；设计稀疏动机与轻律动，不自动加入哼唱、旁白或环境音。未指定模型则分别给 MiniMax 纯标签 Lyrics 与 YuE2 空 Lyrics；技术项采用默认建议，不要求先选格式与 seed。无人声效果仍需试听。

### 特殊人声或反馈

“中段加 rap”先依据叙事与授权设计事件，见 [vocal-performance.md](vocal-performance.md)。

“结尾突然断了”先定位末句/尾奏、歌词密度和上限，保留原词与已选风格；“MP3 码率不符”只处理导出，见 [audio-quality.md](audio-quality.md)。真实反馈与复用见 [feedback-learning.md](feedback-learning.md)，不因一个尾奏问题重写整首。
