# 特殊人声与段落表演

用户提出特殊人声，或叙事明确需要反差时读取。服务故事与听感，不是每首歌增加一段花样。纯音乐默认跳过，不加入歌唱、哼唱、念白、合唱或人声采样。

## 先确定任务，再选手段

Rap 是表演方式；Bridge 是段落功能。主歌可以说唱，桥段可以歌唱或器乐。不要将“中间加 rap”当作标准结构，也不因国风自动加入戏腔或方言。

| 手段 | 可承担的任务 | 位置如何判断 | 不应替代什么 |
| --- | --- | --- | --- |
| Rap / 旋律化说唱 | 密集叙事、态度、节奏密度反差 | 信息较多的主歌；转折；最终副歌前推进 | 不靠堆字数修复缺乏核心句 |
| 故事旁白 | 交代人物、处境、时间变化 | 开头建场；故事转折；结尾回望 | 不复述已经唱清的内容 |
| 轻声念白 | 告白、自问、回答、情绪停顿 | 与内容有关的留白位置 | 不把气声等同耳语、不强行煽情 |
| Ad-lib / 呼应 | 回应关键词、互动、现场感 | 乐句间、重复副歌，避开主词密集处 | 不遮挡歌词、不逐句叠满 |
| 和声/合唱 | 扩展和声、群体表达 | 情绪释放或共同回应处 | 不因“温暖”自动加童声/合唱 |
| 哼唱/无词人声 | 旋律辨识、氛围 | 引入、间奏、收束 | 不进入严格纯音乐作品 |
| 呼吸/叹息 | 自然表演或叙事动作 | 对特定乐句有作用时 | 不当作提升真实感的固定效果 |

“气口念白”仅在影响设计时区分为气声说话、自然换气、叹息或完整旁白。自然气口不等于向 Lyrics 写入“吸气声”。

## 选中之后补齐事件

已有信息沿用，其余合理推荐或每轮问 1–2 个关键问题：

- **目的与内容**：讲什么事还是只需氛围；谁对谁说；台词用户提供还是授权代写；原词能否增加新句。
- **位置与长度**：开头/中段/结尾，再落实到相邻段落；一句还是短段。具体秒数生成前只作计划。
- **表演与关系**：同一叙述者还是另一角色；语速、咬字、情绪、强度；不凭空指定用户未选性别。
- **伴奏与衔接**：什么减法为文字留空间；哪个动机维持连续；如何接回歌曲。

未授权新增歌词时可以设计可选方案，但不混入定稿。原词结构必须保留时说明插入影响；严格无人声同时要求旁白属于冲突，先澄清。用户要求原样朗读时说明遵循待试听，不保证逐字准确。

## 人声事件卡

```yaml
vocal_events:
  - event_id: "VE-01"
    section_id: "B1"
    delivery: "轻声念白"
    purpose: "从回忆转向祝福"
    content_source: "用户授权代写"
    text: "愿下一站，我们都能成为想成为的人。"
    position: "最后一次副歌之前"
    length_plan: "一句"
    performer: "同一叙述者"
    performance: "自然贴近，克制，不做舞台式朗诵"
    accompaniment: "暂减鼓与低音，保留吉他动机"
    transition: "末字尾音后吉他引回副歌"
    rendering: "表演放入 Caption/Style；台词只在获授权后放 Lyrics"
    timestamp_status: planned
    start_sec: null
    end_sec: null
    verification: pending_listen
```

人工示例，不代表执行结果。无特殊人声时 `vocal_events: []`，不为凑表格添加事件。

## 模型适配边界

遵循 MiniMax 的 [workflow-contract.md](workflow-contract.md) 和 YuE2 的 [yue2-guide.md](yue2-guide.md)。字段/标签已核实、自然语言意图可表达、成品是否遵循，是三层不同证据。

1. MiniMax 表演写入 Vocal Details，进入/退出和衔接写入 Arrangement；YuE2 写入自然 Style。
2. Lyrics 只放获授权的演唱/说话文本与已核实标签；事件卡、角色标题、括号制作说明和“在此念白”都可能被唱出，不作为隐形控制。
3. 不新增未经本模型依据支持的 `[Rap]`、`[Spoken]`、`[Whisper]`。可在已核实段落下保留原词，用描述表达表演；无法无歧义映射时保留计划并说明控制不确定，不承诺逐句切换。
4. 只有用户要求精确另录或后期处理时才讨论独立录音/剪辑；本 Skill 不自动录制、分段生成、混音或运行服务。

## 原创设计示例

需求：“温暖毕业歌，中间加一点 rap。”

若用途和原词权限已知，可建议第一次副歌后用旋律化说唱补充共同生活细节，让祝福有依据；保持原有律动，不突变为攻击性风格。伴奏短暂减层，末句放缓接回最终副歌。只要氛围而无新信息时，可推荐一句回应或器乐间奏，但保留用户最终选择。

描述不只写“有说唱”，而写“该段以自然、带微笑感的节奏化叙述呈现具体回忆；保持木吉他动机并减少和声层数，结束时回到可跟唱的核心句”。内容基于用户素材，不编造共同经历。
