# 无歌词、纯器乐与严格无人声

用户提出无歌词轻音乐、纯器乐、无人声 BGM 时读取。吸收用户《MiniMaxMusic3与YuE2无歌词轻音乐提示词指南-20261106.md》，将意图、音乐设计、模型输入、封装兼容性与实际验收分开；指南示例不构成用户长期偏好。

## 先分清歌词与人声

| 用户要求 | 解释与执行 |
| --- | --- |
| “无歌词”，未说明人声 | 一次区分完全纯器乐还是允许哼唱/无词声乐；不默认两者相同，不立即推销有词特殊段落 |
| “纯器乐、严格无人声” | 明确排除歌唱、哼唱、念白、说唱、合唱、人声采样及可辨人声效果；跳过歌手和特殊人声采访 |
| “无歌词，但可哼唱/合唱质感” | 记录为允许无词人声，保留用户选择；不擅加可辨词句或改成严格无人声 |
| “无人声配乐，视频另有解说” | 音乐轨无人声，外部视频解说另算，按 BGM 留白设计，不误判硬约束冲突 |
| “音乐中无人声，但要念白/衬词” | 若属于同一音乐轨则澄清冲突；不能把旁白当器乐 |

Brief 分别写 `lyrics_policy=none / provided / original` 与 `vocal_policy=none / wordless_only / with_words`，以及来源。值未明确时保留 unknown，不为了填表猜测；用户已明确不再重问。

## 将用途转成具体音乐行为

先用上下文和相关记忆提出方案，只问会改变音乐角色的缺口。器乐不必虚构歌词人物、核心台词或歌手人设；表达由主题、动机、音色和发展承担。

| 用途 | 可优先设计的行为 | 不自动假定 |
| --- | --- | --- |
| 阅读/安静办公 | 背景位置，短动机，小幅变化，较稳定密度，减少突然独奏/跳变 | 必须显眼 Hook 或大高潮 |
| 睡前/放松 | 柔和起音、稀疏音符、平缓动态；节拍按目标 | 无鼓统一适用、音乐有睡眠疗效 |
| 咖啡/空间 | 温和律动、轻巧旋律、适量留白，可选鼓刷或摇摆 | 所有轻音乐都无鼓或只有钢琴 |
| 解说背景 | 克制主旋律与填句，维持稳定支撑，为说话留空间 | 写了“轻柔”就不会抢解说 |
| 独立聆听 | 清楚主题、回应、展开和回归，音色/和声有发展 | 无人声就只能单调循环 |

将选择落实为：**用途/前背景 → 风格与情绪走向 → 器乐主旋律 → 声部职责 → 律动与密度/动态 → 有顺序的段落变化 → 结尾或循环 → 必要排除项**。

- 先交代谁承担主旋律，再排除人声；例如“中音区木管短动机，弦乐只做轻长音”，优于只写“不要唱”。
- 节奏、低频、和声、主奏/回应职责清楚，使用少量有作用的声部，不把乐器目录当编曲。
- 无鼓时让和声、音区、触键或回应推进；允许鼓的版本不能残留“全曲无打击乐”。
- 少量、明确的人声排除写在 Caption/Style，不编造 negative prompt 框；不把禁用词列表无限加长当优化。
- 避免与目标冲突的主唱、choir、vocal chop、吟唱/呼吸人声等描述；“温暖”“有呼吸感”可改写为具体器乐触键、留白与动态，不靠暗示歌手的词营造质感。
- 收尾完整与无缝循环是两个目标，明确主次；文字提出循环意图，精确接缝仍待实际音频检查。
- BPM/调性有明确目的才填，导出格式/码率不进编曲描述。没有中英对照实测，不声称哪种描述语言更稳定。

## 模型输入与边界

| 项目 | MiniMax Music 3 | YuE2 |
| --- | --- | --- |
| 主描述 | Caption 三部分；Vocal Details 保留，写无人声并说明器乐主奏 | 自然 Style，同样写器乐主奏、声部和排除范围 |
| 文本起步 | 必要纯段落标签为 Skill 建议；支持空词的工作流也可真正留空 | 空 Lyrics + 纯器乐 Style 为低门槛探索，不能单独保证无人声 |
| 更明确的结构控制 | 不虚构统一器乐开关 | 作者乐谱路线：先规划，再把 Vocal 音符移入 Ins，使 Vocal 休止，再生成；需要实际接入/检查 |
| 共同边界 | 输入可接受、整图可保存、实际无人声三者分别核对 | `mode=melody` 只是旋律规划，`ABC_planning=开启` 不等于做了移轨 |

MiniMax 纯标签示例：

```text
[Intro]
[Instrumental]
[Outro]
```

它不是官方纯音乐硬开关。YuE2 的空 Lyrics 要真正空白；不填“无歌词”“留空”“请不要唱歌”等占位说明，也不使用虚构歌词来满足导出。若已有获核对的乐谱路线使用曲式标签，按其乐谱和输入校验处理，不照搬 MiniMax 标签清单。

## 原创完整描述示例：解说背景

以下只演示字段组织，尚未生成/试听。钢琴、木吉他、稀疏低频和无鼓均为教学选择，不成为所有轻音乐的默认编制。实际交付还按文档规范补本次参数、导出和手动步骤。

### MiniMax Caption

```text
Global Metadata:
温和的原声器乐配乐，用于知识视频解说的背景。稳定、舒展的慢速律动，情绪从轻微思考感逐渐安定，整体保持低密度与平缓动态，不追求突出高潮。

Vocal Details:
全曲纯器乐，无歌唱、哼唱、念白、说唱、合唱、人声采样及人声效果。主旋律由中音区钢琴承担，只演奏简短、平缓的动机，乐句之间充分留白。木吉他以稀疏分解和弦提供陪伴，低频声部仅在句尾轻柔支撑，不与主旋律争抢注意力。

Arrangement:
先以稀疏钢琴和弦引入，再出现短主题，木吉他轻轻加入。主题重复时只改变少量句尾与和声，避免连续填句、突然独奏和音量跳变。中段稍增加和声宽度，保留相同密度，为视频讲话持续留出空间。末段减少声部，回到开头动机，以完整落定的和弦与自然尾音结束。全曲无鼓和打击乐，不加入环境录音。
```

Lyrics 使用上方纯标签方案，前提是输入和保存链路均兼容；如已核对工作流接受真正空词，也可采用空词策略，记录为待比较方案。

### YuE2 Style

```text
温和的原声器乐配乐，用于知识视频解说背景，稳定、舒展的慢速律动，情绪从轻微思考感逐渐安定，低密度与平缓动态。全曲无人声，无歌唱、哼唱、念白、说唱、合唱、人声采样及人声效果。中音区钢琴只演奏简短、平缓的动机，句间充分留白；木吉他以稀疏分解和弦陪伴，低频声部仅在句尾轻柔支撑。稀疏钢琴和弦引入后呈现短主题，木吉他轻轻加入；主题重复只小幅改变句尾与和声，中段略扩和声宽度，保持密度稳定，减少抢注意力的填句。末段减少声部，回到开头动机，以完整落定和弦及自然尾音结束。全曲无鼓和打击乐，不加入环境录音、突然独奏、明显音量跳变或大幅高潮。
```

**YuE2 Lyrics：真正留空。** 只在操作说明中写“保持为空”。ABC 与 Music 两处 Style/空 Lyrics 要一致，清除旧歌残留文本。本方案为文本探索，不表示已完成作者推荐的器乐移轨，也不保证无人声。

## YuE2 乐谱路线：只描述实际具备的步骤

作者公开路线的核心为：规划与目标曲式一致的 ABC → 将 Vocal 旋律事件移入 Ins → Vocal 保持休止及适用和弦 → 检查乐谱与转换记录 → 用处理后的 ABC 及空词或匹配曲式标签生成。

不是仅改轨名、将乐器名填进 Style，或把 ABC_planning 设为开启。转换时声部重叠可能使原 Ins 内容缩编，需要检查转换结果；谱面人声休止仍不保证音频绝无人声。

官方节点可接收 ABC，不等于用户现有图已经包含转换。本 Skill 仍只交创作资料与手动检查清单，不自动下载安装作者脚本、编辑 ABC、改图或连接服务。用户后续明确要求额外制作时再处理，不把这条路线设为普通交稿的强制前置。

| 分层 | 核对内容 | 不通过或未知时 |
| --- | --- | --- |
| 模型编码 | caption/style、空词或纯标签是否能传入 | 未知标 pending，不从第三方报错判断模型不支持 |
| 收词节点 | 是否拒绝空字符串或清理后为空 | 标明需允许空词；不能加“啦啦啦”绕过 |

| 音频验收 | 全曲是否仍有可辨人声、是否服务用途 | 等真实试听，不能由日志成功/ASR 无文本替代 |

## 针对问题迭代

| 实际问题 | 优先调整 |
| --- | --- |
| 出现人声 | 查残留 Lyrics、人声描述和标签；强化器乐职责与必要排除；YuE2 再核对乐谱路线，不无限换 seed |
| 抢解说/注意力 | 减旋律显著度、密度和填句，再收敛动态；与实际解说合听 |
| 独立听太平 | 加主题回应、轻微变奏与回归，保留用户选定能量 |
| 情绪过悲 | 调和声安定感、旋律走向与音色，不自动只加速 |
| 突然爆发 | 清理冲突编排，写明全曲动态与中段发展幅度 |
| 尾奏截断 | 查实际结束与上限、简化结构或留收尾空间；上限不是精确时长 |
| 编码/保存失败 | 查保存节点及歌词校验，不能靠修改音乐描述修复 |

验收必须覆盖完整音频：可辨人声、旋律/伴奏职责、节奏/动态、用途、主题发展和结尾。仅 ASR 未识别到文字不能排除哼唱/合唱/人声采样。未取得真实音频，均保留 PENDING，不记稳定率或听感改善。

将本首人声政策、输入策略、封装检查和试听结果分别写入 [学习记录](feedback-learning.md)，不将“轻音乐=无鼓”或一次成功推广为全局经验。
