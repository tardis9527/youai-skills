# 生图 Skill（中文项目版）

本 Skill 参考 Codex 内置 `imagegen`，用于为当前项目生成或编辑图片。操作说明和示例使用中文；保留 CLI 脚本的英文参数名，保证与实际命令一致。

## 先选执行方式

1. **默认：内置 `image_gen` 工具。** 普通生成、编辑、批量素材和透明背景请求都先走这条路径；不需要 `OPENAI_API_KEY`。
2. **备选：`scripts/image_gen.py`。** 仅当用户明确要求或确认使用 CLI、Image API、指定模型或其专属参数时使用。真实请求需要 `OPENAI_API_KEY`、`openai` Python 包和网络权限。
3. 用户说“批量”只表示需要多张图，并不等于选择 CLI。内置路径下，每个不同素材或变体分别调用一次工具。
4. 内置工具不可用或失败时，说明 CLI 备选及其 API Key 要求，得到用户明确选择后再切换。不要悄悄从内置工具或 CLI 的 `gpt-image-2` 切到 `gpt-image-1.5`。

## 判断任务

- 用户要改变原图且保留其余部分：**编辑**。逐项写明“只改什么、必须保留什么”，默认另存新文件。
- 图片只用于参考风格、构图或氛围：**生成**。没有输入图时也是生成。
- 每张输入图标明角色：编辑目标、风格参考、合成来源等。多张图用“图 1、图 2”对应。
- 需要不同素材时分别写提示词；同一提示词的多个变体才适合 CLI 的 `--n`。
- 项目已有 SVG、可编辑图标或代码图形时，按项目原有方式修改；明确要求照片、插画等位图时才调用生图工具。

## 工作流程

1. 确定交付物的用途、数量、画幅、必须出现的文字、避免项和输入图角色；只问会阻碍完成的关键缺失信息。
2. 按 [提示词指南](references/prompting.md)整理需求。具体提示词只需结构化；笼统提示词可适度补充构图和用途，不能擅自增添人物、品牌、口号或情节。
3. 默认调用内置 `image_gen`。编辑本地图片前，先用 `view_image` 把它载入对话上下文；不要声称内置工具可任意按文件路径直接编辑。
4. 请求透明图时，直接要求真正透明的背景，并保留 alpha 通道。
5. 检查主体、构图、文字是否准确，以及编辑时不应变化的部分。迭代时每次只调整一个明确问题，并重复重要约束。
6. 预览或头脑风暴可以直接在对话中展示。项目素材需将选定成品保存到项目内，并更新引用它的代码或文件；不要让项目只引用 `$CODEX_HOME/generated_images/...` 下的临时产物。
7. 用户指定了保存位置就按指定位置交付。除非明确要求替换，不覆盖已有素材，可用 `-v2` 等文件名。多素材任务要保存每件最终交付物。
8. 报告最终文件路径、使用的提示词，以及使用内置工具还是 CLI。

## 两条路径的边界

内置工具的生成文件通常位于 `$CODEX_HOME` 下。不要假设它有指定目标路径、`quality`、`input_fidelity`、遮罩、输出格式等 CLI 参数；需要项目文件时，生成后再复制或移动。

明确选择 CLI 后，先读 [CLI 操作说明](references/cli.md)。`generate`、`edit`、`generate-batch` 是 CLI 的三个子命令；`generate-batch` 不是第三种执行方式。CLI 默认模型为 `gpt-image-2`。CLI 中的 `gpt-image-2` 不支持 `background=transparent`；要改用 `gpt-image-1.5` 的原生透明输出，先征得用户明确同意，除非用户已经指定该模型。不要修改随附 `scripts/image_gen.py`；需要缺失能力时先向用户说明。
